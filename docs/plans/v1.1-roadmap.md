## Before planning (done for feature 1)

- **Feature 1** (design: [technical design §5.6](../design/technical-design.md#56-resume-an-old-session-v11-built-hand-check-pending)); the three spikes ran, see the [spike report](spike-report.md):
  - **R1, Claude Code spike:** `claude --resume <id>` with DuoHive's per-launch `--settings`, `--append-system-prompt` and `--mcp-config`; whether the `SessionStart` hook payload carries a session id and whether it is the original after a resume; which session-file fields give the title, branch and size; how a directory maps to its folder under `~/.claude/projects/`.
  - **R2, OpenCode spike:** does `opencode session list --format json` carry each session's directory, title, branch, size and last-written time, and does `--session` resume it from there under `--standalone` and `OPENCODE_CONFIG`?
  - **R3, OpenCode plugin:** can the plugin report its session id in the hook payload?
  - Recording each running agent's CLI session id from its hooks (`sessions.cli_session_id`, a store migration), so a session in use by another agent can be refused.
  - Claude Code's session files are its internal format: the tested-versions list covers them.
  - At planning, the UI spec's key table, key map, footer, node menu and Keys screen get `r` (UI §4.13, *Where `r` appears*).

## Open items before merge

Feature 1 is built and reviewed task by task on `feat/resume-session`; it is not released and not merged. These are open:

- **(a) The hand check.** [Spike report R4](spike-report.md#r4-hand-check-author): Claude Code and OpenCode in iTerm2 at 80x24 and 160x48. For the author.
- **(b) AUTHOR DECISION: OpenCode entries omit branch and size.** `opencode session list` carries no branch and no size (spike R2), so an OpenCode entry shows its title, age and `worktree <task-id>` only, and the picker's search matches the title only. TD §5.6 now says so; the PRD and UI §4.13 still describe a branch and a size for every entry. Confirm the built behaviour and reword the PRD and UI, or choose another way.
- **(c) AUTHOR DECISION: a fresh idle OpenCode session is "in use" only after its first prompt.** OpenCode's plugin has no session id before the first prompt (spike R3), so another agent's session that has not yet had a prompt cannot be marked `in use by` (it does not yet exist in the list either). Confirm, or change the PRD and TD wording.
- **(d) Known limitation: hashed long directory names (Claude Code).** A directory name long enough that Claude Code truncates and hashes its project folder name is not matched; those sessions are not listed. Untested against a real long path.
- **(e) The count label call.** The UI spec's `(1 of 36)` was implemented as `{position} of {visible}` (the highlighted row among the entries the search leaves); `0 of 0` when nothing matches. Confirm or change.
- **(f) Final review triage** (reviewer's, none blocking):
  - **Shipped as-is:** engine events from `worktree_rows` are dropped on the replace-rejection and queued paths and `worktrees_stale` is set even if the launch failed; a trailing-slash directory encodes a trailing `-` and astral characters may encode as two `-` (Claude reader); `isMeta` user records are not filtered and a record's `cwd` is compared raw; the 80x24 node-menu snapshot overlaps the Needs you border and `↓ more` is cosmetic; an entry both in use and recent shows both marks and `size_text` can overflow in its column.
  - **Follow-up:** the engine's `last_listed` goes stale after an `org.toml` reload that changes an agent's CLI or directory (store the CLI with the cache and refuse on a mismatch); a Claude `/clear` or an in-CLI `/resume` keeps the old session id (first id wins); no cross-crate end-to-end test (a temp-HOME fixture); OpenCode runs one command per distinct directory, so a per-project dedupe would cut the wait; the worktree resume's two cwd sources and its test gaps; bidi and zero-width (`Cf`) characters are not stripped by `clean()` (R.9, R.13); id-rule tests and a code comment for the long-name limitation; consolidating the session-id rule (core `signals.rs` and `claude_sessions.rs`) into one function and the merge test's `None` tags; a near-vacuous R.11 test; the Agent pane's help column does not list `r resume`; the dead `ResumePicker.confirm` field, picker test gaps, `error_note` as a bool, and a second `SessionsListed` while the picker is open being dropped.
  - **Fixed in the final fix wave:** a v1 `settings.toml` binding of `r` to another action beats Resume's default (see the keymap rule below); an empty `*.jsonl` no longer turns an empty list into `unrecognised Claude Code session format`; `r` shows `reading <CLI>'s sessions…` until the answer arrives (no lockout); the picker's search matches the cleaned text it shows; an answer is dropped while a context menu is open; the engine does not cache a listing for an unknown agent; `resume_blocked_while_replacing` asserts exactly one launch; the OpenCode runner's `try_wait` error arm kills the group and waits the child (not unit-tested: `try_wait` cannot be made to fail); the missing `action_for` test after rebinding Resume.
- **(f2) The keymap rule for a saved `r`.** In v1 `r` was free, so a user may have saved `[keys] move = "r"`. A saved binding of `r` to another action in a shared context wins over Resume's new default: Resume is left without a key (an unbound Resume still works from the node menu), and the Keys screen shows `resume: r is taken by move · rebind it in Keys`. A saved `resume = "x"` is always honoured, with no notice. Confirm.
- **(g) A flaky test, not caused by this work.** `opencode::plugin_tests::plugin_replays_recorded_events` (node-driven) failed once under load and passed alone and on re-run.
