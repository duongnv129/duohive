## Before planning (done for feature 1)

- **Feature 1** (design: [technical design §5.6](../design/technical-design.md#56-resume-an-old-session-v11-built-hand-check-pending)); the three spikes ran, see the [spike report](spike-report.md):
  - **R1, Claude Code spike:** `claude --resume <id>` with DuoHive's per-launch `--settings`, `--append-system-prompt` and `--mcp-config`; whether the `SessionStart` hook payload carries a session id and whether it is the original after a resume; which session-file fields give the title, branch and size; how a directory maps to its folder under `~/.claude/projects/`.
  - **R2, OpenCode spike:** does `opencode session list --format json` carry each session's directory, title, branch, size and last-written time, and does `--session` resume it from there under `--standalone` and `OPENCODE_CONFIG`?
  - **R3, OpenCode plugin:** can the plugin report its session id in the hook payload?
  - Recording each running agent's CLI session id from its hooks (`sessions.cli_session_id`, a store migration), so a session in use by another agent can be refused.
  - Claude Code's session files are its internal format: the tested-versions list covers them.
  - At planning, the UI spec's key table, key map, footer, node menu and Keys screen get `r` (UI §4.13, *Where `r` appears*).

## Open items before merge

Feature 1 is built and reviewed task by task on `feat/resume-session`; it is not released and not merged. These are open:

- **(a) The hand check.** [Spike report R4](spike-report.md#r4-hand-check-author): Claude Code and OpenCode in iTerm2 at 80x24 and 160x48. For the author.
- **(b) AUTHOR DECISION: OpenCode entries omit branch and size.** `opencode session list` carries no branch and no size (spike R2), so an OpenCode entry shows its title, age and `worktree <task-id>` only, and the picker's search matches the title only. The PRD, UI §4.13 and TD §5.6 still describe a branch and a size for every entry. Confirm the built behaviour and reword the PRD and UI, or choose another way.
- **(c) AUTHOR DECISION: a fresh idle OpenCode session is "in use" only after its first prompt.** OpenCode's plugin has no session id before the first prompt (spike R3), so another agent's session that has not yet had a prompt cannot be marked `in use by` (it does not yet exist in the list either). Confirm, or change the PRD and TD wording.
- **(d) Known limitation: hashed long directory names (Claude Code).** A directory name long enough that Claude Code truncates and hashes its project folder name is not matched; those sessions are not listed. Untested against a real long path.
- **(e) The count label call.** The UI spec's `(1 of 36)` was implemented as `{position} of {visible}` (the highlighted row among the entries the search leaves); `0 of 0` when nothing matches. Confirm or change.
- **(f) Deferred review notes** (minor, none blocking; the implementers' and reviewers' lists):
  - Engine: events from `worktree_rows` are dropped on the replace-rejection and queued paths of `resume_session`; `worktrees_stale` is set even if the launch failed; a worktree resume uses the cached `session.dir` for `ResumeTarget.cwd` but the live row path for the launch cwd; four test gaps (`resume_blocked_while_replacing` should assert exactly one launch, the errored-kill window id, the spec's `resume` while waiting for the inventory, worktree resume with a failing launch).
  - Claude reader: zero-length `*.jsonl` files count toward the `unrecognised Claude Code session format` error, so a lone just-started session shows an error instead of an empty list; a trailing-slash directory encodes a trailing `-`; astral characters may encode as two `-` (UTF-16); bidi and zero-width characters and `isMeta` user records are not filtered; the session's recorded `cwd` is compared raw, not canonicalised; id-rule tests for over-long and non-ASCII stems; a code comment on the long-name limitation.
  - OpenCode reader: the session-id rule exists twice (core `signals.rs` and `claude_sessions.rs`, equivalent), to consolidate into one function; the merge test uses `None` tags; the `try_wait` error arm should kill and wait the child.
  - Binary: `closed_input_channel_is_ignored` cannot see a panic in the spawned task; a 50 ms sleep in `request_does_not_block_the_caller`; a request after the main runtime shuts down is dropped silently (moot at exit).
  - Keys: the Agent pane's help column does not list `r resume`; the 80x24 node-menu snapshot overlaps the Needs you border (cosmetic); a keymap unit test that after rebinding `action_for(AgentPane, key) == Resume` is missing.
  - Picker: the unread `ResumePicker.confirm` field; `clean()` does not strip bidi and zero-width characters; an entry both in use and recent shows both marks; some test gaps (cancel with the cursor on row 1, `tab` and `ctrl+c`, the in-use footer render, a misnamed click test); `size_text` should use `saturating_add`; `error_note` should be a bool cleared with the footer note; `m.menu` open when an answer arrives is not checked; the spike R1 to R3 docs have optional wording polish.
- **(g) A flaky test, not caused by this work.** `opencode::plugin_tests::plugin_replays_recorded_events` (node-driven) failed once under load and passed alone and on re-run.
